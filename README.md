# uzum-moysklad-sync

Синхронизация Uzum Market (FBO) → МойСклад без отчёта комиссионера.
Маппинг полей и статусов: [docs/mapping.md](docs/mapping.md).

## Что делает

1. Поставка (накладная) в Uzum → **Перемещение** «Фулфилмент Евгений» → «Uzum»;
   после приёмки — сверка принятого с отправленным, недостача → **Списание**.
2. Новый заказ Uzum → **Заказ покупателя** (склад «Uzum», ID заказа во внешнем коде,
   резерв позиций).
3. Выкуп (TO_WITHDRAW) → **Отгрузка**, привязанная к заказу.
4. Отмена до выкупа → отмена заказа (частичная отмена уменьшает позиции).
5. Возврат после выкупа → **Возврат покупателя** на склад «Uzum».
6. Раз в час — сверка остатков склада «Uzum» с Uzum API (Uzum теряет и находит
   товары): стабильные расхождения автоматически выравниваются Оприходованием /
   Списанием + уведомление в Telegram (`STOCK_AUTOCORRECT`). Разовое выравнивание —
   команда `align-stock` (использовать и для первичной загрузки остатков).

Доп. поля («ID заказа Uzum», «Дата доставки», «Комиссия», «Логистика») и статусы
(«Uzum: в обработке/выкуплен/отменён/возврат») создаются автоматически при `init`.

Матчинг товаров: штрихкод Uzum в карточке МойСклад → артикул = skuTitle → код
модификации. Не найден — документ не создаётся, лог + Telegram, повтор следующим циклом.

## Запуск

```bash
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить UZUM_TOKEN, MS_TOKEN и пр.
.venv/bin/python main.py init      # проверка доступов, создание доп.полей/статусов
.venv/bin/python main.py dry-run   # план без создания документов
.venv/bin/python main.py run       # рабочий цикл
```

CLI: `sync-orders`, `sync-shipments`, `sync-returns`, `sync-transfers`,
`check-stock`, `align-stock`, `sync-all`, `run`; флаг `--dry-run`.

Идемпотентность: SQLite (`sync.sqlite3`) + `externalCode` в МойСклад —
повторный запуск ничего не дублирует.
